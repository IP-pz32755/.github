<h2>速度不是一个数字，是三种体验</h2>
<p>说住宅 IP「快不快」，实际包含三种不同的体验：打开页面快不快（延迟）、上传素材快不快（上行带宽）、以及并发操作时会不会卡（带宽与连接数）。三种体验由不同因素决定，选型时要分开看。</p>
<p>把它们混在一起谈，就会出现「买了高带宽但打开页面还是慢」这类困惑。</p>

<p>第二行最容易踩坑。多数报价只写下行，而上行才是跨境业务的瓶颈。上传类操作多的，必须单独确认上行数值。</p>

<h2>延迟怎么判断</h2>
<p>延迟由物理距离决定，跨洲链路存在基础延迟，无法消除。所以判断标准不是绝对值，而是与同地区其他方案对比。</p>
<p>比延迟数字更重要的是稳定性。延迟略高但平稳，体验尚可；延迟不高但波动大，体验很差。因为波动会让人无法预期，操作节奏被打断。</p>

<h3>丢包比延迟更影响体验</h3>
<p>丢包会触发重传，重传带来的等待远高于基础延迟。监测时要同时记录丢包率，只看延迟会漏掉更严重的问题。</p>
<h3>为什么高峰期会变慢</h3>
<p>住宅带宽是共享的，同一线路上的用户在高峰期同时使用，每人分到的带宽下降。这是住宅资源的固有限制，不是故障。判断方法是看是否只在固定时段变慢。</p>

<h2>带宽怎么选</h2>
<p>先算自己的实际需求。纯店铺运营（后台操作、图片上传）需求不高，中等带宽足够；带视频素材的，上行需求陡增；做直播的，需要持续上行且抖动小，属于要求最高的一类。</p>
<p>不要按「越大越好」选。带宽是成本大头，超过需求的带宽是纯浪费。也不要不留余量，否则高峰期会明显卡。</p>

<h2>采购时要问的四项</h2>
<p>一，上行多少。二，带宽是独享还是共享。三，是否有流量上限，超出如何计。四，并发连接数是否受限。</p>
<p>四项里，第二项与第四项最常被含糊处理。共享带宽在高峰期会明显衰减；并发限制严的，多开几个页面就触顶，表现为部分请求失败。</p>

<h2>实测怎么做</h2>
<p>三项测试。一，连续测延迟与丢包，至少跨两个时段（高峰与非高峰）。二，测上行与下行，用大文件验证真实速率。三，多任务并行测试，同时开多个页面与上传任务，观察是否明显变慢。</p>
<p>三项都要记录数据。凭感觉判断「快慢」，在不同时段会得出相反结论。</p>

<h2>速度不达标怎么排查</h2>
<p>顺序一，测本地到网关，排除本地网络问题。顺序二，测到目标站点，看是否中间某段突增。顺序三，换 DNS 复测，排除解析到远端节点。顺序四，错峰复测，排除拥塞。顺序五，才联系服务商。</p>
<p>顺序反了，往往会在「服务商说正常、你觉得很慢」之间来回消耗。</p>

<h2>先问上行，再谈带宽</h2>
<p>询价时把顺序调一下：第一句问上行多少，第二句才问带宽档位。这个顺序会让对方知道你是懂行的，也能立刻筛掉一批只有下行数字的方案。跨境业务里，上传失败、进度条卡住、素材传一半断掉，几乎都是上行不足导致的，而下行往往还很宽裕。</p>
<h2>常见问答</h2>
<h3>住宅 IP 一定比机房慢吗</h3>
<p>通常慢一些，但不是绝对。真正的差别在高峰期表现与上行带宽。</p>
<h3>升带宽能降延迟吗</h3>
<p>不能直接降，但能减少拥塞导致的延迟升高。若瓶颈是路径绕行，升带宽无效。</p>
<h3>多少延迟算正常</h3>
<p>取决于距离。跨洲的基础延迟无法消除，判断标准是与同地区方案对比，而不是绝对值。</p>
<h3>需要买很高带宽吗</h3>
<p>多数店铺运营不需要。把预算放在独享与稳定性上，比堆带宽更有效。</p>
